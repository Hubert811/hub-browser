# 模板字符串/正则的跨层转义阶梯

## 问题现象

- 发出去的 evaluate 表达式 SyntaxError，或正则匹配错
- 现象 A：`\s` 变成 `s`、`\n` 变成真换行 → `Invalid regular expression: missing /`
- 现象 B：多语言/多工具链（脚本 → shell → python → 文件）接力后，反斜杠被吃掉多层

## 根因

模板字面量本身会处理转义：`"\s"` 求值后是 `s`（非法转义丢弃反斜杠），`"\n"` 是换行。正则写在模板里要**双写**才有 `\s`。

跨层传递时每层字符串处理都会吃一层：

```
run_code 模板 (\\ → \) → bash (可能不处理) → python 字符串 (\ → ) → 文件 → 运行时模板 ( → 真转义)
```

## 修复方案

1. **文件里模板字面量中的正则要双写**：`replace(/\\s/g, ...)`，让最终 evaluate 的表达式保留 `\s`。
2. **跨层用显式构造**：python 用 `chr(92)` 拼反斜杠，避免字符串转义。
3. **能用函数式 evaluate 就不用字符串**（`page.evaluate(fn)` 无转义问题）。
4. 改完立即跑一次真实调用验证，不要只看"编译通过"。

## 通用性

- 所有把 JS 代码放进模板字符串再 evaluate 的适配器
- 多工具链接力生成文件时

## 验证建议

- 打开发出的 EXPR（dashEval 错误信息里有完整表达式），肉眼检查正则字符
- 用 `grep -n "replace(/"` 检查文件里是 `\n` 还是 `
`
